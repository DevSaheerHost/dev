One camera, three consumers

cctv-recorder.sh

A V4L2 device can only be opened once. Three processes wanting the same camera is the problem that shapes the whole system, so one ffmpeg reads /dev/video0 and fans the frames out: ten-minute H.264 segments onto the USB drive, a single JPEG rewritten in place for the fallback view, and a low-latency MPEG-TS stream on loopback for WebRTC. Everything downstream is a reader of those three, never of the camera.

Refusing to record onto the wrong drive

cctv-recorder.sh

A mountpoint being busy does not mean it is your disk. This checks the filesystem UUID and type of whatever is actually mounted and unmounts it if it is something else, so plugging in a phone or a stranger’s stick can never start filling it with footage. The read-write flag is checked too, and the caller then proves writability with a real file rather than trusting the flag.

storage_ok() {
    if ! mountpoint -q "$MOUNT"; then
        mount "$MOUNT" >/dev/null 2>&1 || return 1
    fi

    local src fs opts actual_uuid

    src=$(findmnt -rn -M "$MOUNT" -o SOURCE 2>/dev/null)
    fs=$(findmnt -rn -M "$MOUNT" -o FSTYPE 2>/dev/null)
    opts=$(findmnt -rn -M "$MOUNT" -o OPTIONS 2>/dev/null)
    actual_uuid=$(blkid -s UUID -o value "$src" 2>/dev/null)

    if [[ "$actual_uuid" != "$UUID" || "$fs" != "vfat" ]]; then
        umount "$MOUNT" >/dev/null 2>&1 || true
        return 1
    fi

    case ",$opts," in
        *,rw,*) ;;
        *) return 1 ;;
    esac

    return 0
}

A ring buffer that never eats the file being written

cctv-recorder.sh

Old footage is deleted to make room, but only above 80% and only down to 75% — hysteresis, so it is not deleting one file every few seconds at the boundary. Only cctv_*.mp4 is ever touched, nothing else that happens to be on the drive, and while recording is live the newest file is protected because ffmpeg still has it open.

# Delete only cctv_*.mp4 recordings.
# When recording is active, protect the newest file.
prune_storage() {
    local protect_latest="$1"
    local usage latest name
    local -a files

    usage=$(usage_percent) || return 1
    (( usage < 80 )) && return 0

    mapfile -t files < <(
        find "$OUT" -maxdepth 1 -type f \
            -name 'cctv_*.mp4' -printf '%f\n' | sort
    )

    latest=""
    if (( ${#files[@]} > 0 )); then
        latest="${files[${#files[@]}-1]}"
    fi

    for name in "${files[@]}"; do
        if [[ "$protect_latest" == "1" && "$name" == "$latest" ]]; then
            continue
        fi

        rm -f -- "$OUT/$name"

        usage=$(usage_percent) || return 1
        (( usage < 75 )) && return 0
    done

    usage=$(usage_percent) || return 1
    (( usage < 80 ))
}

Basic Auth alone would let any website stop the recorder

cctv_web.py

The browser attaches Basic-Auth credentials to any request to this host, including a form POST from a hostile page in another tab. That page could have stopped the recorder. Three cheap layers close it: a custom header that cannot be set cross-origin without a CORS preflight this app never answers, an Origin that must match, and Sec-Fetch-Site where the browser offers it.

@app.before_request
def api_csrf_guard():
    if request.method in ("GET", "HEAD", "OPTIONS") or not request.path.startswith(_API_PREFIXES):
        return None
    if request.headers.get("X-CCTV-Request") != "1":
        return jsonify(error="Missing request header"), 403
    origin = request.headers.get("Origin")
    if origin and origin != request.host_url.rstrip("/"):
        return jsonify(error="Cross-origin request blocked"), 403
    site = request.headers.get("Sec-Fetch-Site")
    if site and site not in ("same-origin", "none"):
        return jsonify(error="Cross-site request blocked"), 403
    return None

What this project demonstrates

Linux device troubleshooting at the V4L2 and ALSA level, a video pipeline that has to serve three consumers from one device, storage that fills up and has to be managed without losing the file being written, service automation that survives reboots and power cuts, and a web interface that is safe to expose on a network.
